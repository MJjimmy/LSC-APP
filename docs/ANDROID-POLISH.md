# LSC Android polish — implementation and acceptance

## Scope and source

The existing Kotlin/XML/native-Welcome + trusted-WebView architecture remains. The installed package is **com.example.lsc_app**; `lsc_app` was an abbreviated README label, not a package rename. Version 1.4.2 / code 7 on `ui-fix` adds light-only presentation, retains the removed native top toolbar/loading strip and includes the earlier Google repeated-tap/cancel fix.

PHP source is **not part of this Android repository**. A separate existing backend checkout was read only to verify routes. No PHP, database, server authentication, CSP, cookie or permission changes were deployed by this work. No dependency, storage permission, JavaScript interface, Firebase configuration or credential was added.

Verified existing page routes: `dashboard.php`, `groups.php`, `group.php`, `tasks.php`, `profile.php`, `files.php`, `notifications.php`, `calendar.php`, `help.php`; authentication routes remain separate. The existing invitation route is `invite.php?token=` with a 32-byte lower-case hex token generated by `InvitationService`. The backend validates expiry, recipient and CSRF before acceptance; opening a link never accepts it natively.

## Implemented

- LSC book/connection brand: local adaptive foreground/background, separate monochrome/themed icon, API 24/25 vector fallback, OS splash on API 31+, static launch-window background on older Android. No startup timer or artificial wait.
- Explicit light platform theme in day and night configurations, light Welcome/error/dialog/splash surfaces and contrast-conscious labels. Native Force Dark and WebView algorithmic darkening are disabled. Light-theme `isLightTheme` keeps WebView colour-scheme preference light; website presentation remains server-owned, with no injected CSS/JavaScript. Navy/copper remain brand accents. Light status/navigation bars use dark icons where supported; API 24/25 retain a fixed navy navigation bar because dark navigation icons require API 26. This is a contrast fallback, not device-night behavior.
- No extra native top toolbar: the Back/title/Refresh/Home row was removed at the owner's request. Real website navigation and safe Android Back remain. Native bottom tabs are not duplicated without a coordinated PHP presentation mode.
- One WebView/session. No native top loading line or reserved progress-bar space. Only an exact trusted-document refresh may keep its prior content visible; foreign redirects retain independent start/commit guards. Indeterminate file-operation feedback remains separate from page presentation.
- Accessible, scrollable error screen with Retry and safe Welcome exit. Main-frame failures are separated from subresource/stale failures. TLS errors always cancel. Retry preserves the intended trusted URL, except one-shot OAuth/exchange/logout/download routes, which safely return to login instead of replaying an authorization request as GET.
- Pure JVM-tested destination, retry, refresh, error, history and invitation policies. Back skips one-shot/foreign URLs and does not cross from an expired/login session into the prior account's cached workspace. At a workspace root without safe history it exits normally.
- Existing WebView save/restore and download-stage ownership retained. Restored main-frame URLs must remain trusted. Welcome/buttons/error content accommodate font scaling and insets; touch controls are at least 48dp.
- Separate indeterminate upload-selection/validation and download/save feedback. No fake upload percentage or server upload-success claim: selected files still require the website's actual submission and validation.
- Completed saved downloads can Open/Share the **user-chosen content URI**, only when read permission is actually granted. Chooser intents grant read access only, carry ClipData, and never contain cookies or remote private URLs. No FileProvider is required for an already-granted document-provider URI. Missing read grants still allow saving, without offering unsupported actions.
- Download action dialogs are dismissed on account/navigation boundaries and closure. They recheck the in-memory generation and cookie binding before launching another app. Existing same-origin, redirect/HTML/100 MB rejection, staging, cancellation and 10-file/100 MB combined upload limits remain unchanged.
- Strict HTTPS invitation entry filter and native long-press Share invitation for actual invitation anchors on supported workspace pages. Extra parameters, fragments, credentials, spoofed hosts, nonstandard ports and malformed tokens are rejected. No HTML scraping or token logging.

## Boundaries and remaining configuration

### Backend presentation (not implemented here)

Keep existing web navigation until an explicit presentation-only app mode can safely remove duplicate controls. Recommended PHP follow-up: 48px touch targets, stacked group/task/file cards instead of wide tables, readable form spacing/input types, mobile chat bubbles and composer, and meaningful authenticated empty/error states. Preserve normal browser layouts, CSP and all server-side authorization. A presentation flag must never authenticate or authorize anyone.

### Native Home data (not faked)

No configured authenticated mobile Home JSON API is present in this Android project. The real existing dashboard remains in the WebView. A future server contract should provide the current user's display name, permission-filtered memberships, due tasks with timezone-qualified timestamps, notification summaries and server-generated destination links; define 401/403, loading/empty/error and pagination behaviour. Such a contract is a proposal, not a newly implemented or called endpoint.

### HTTPS App Links

The Android manifest is ready for the canonical host's exact `/invite.php` path. **Automatic verified opening is not claimed.** The server must publish `/.well-known/assetlinks.json` over HTTPS with `delegate_permission/common.handle_all_urls`, package `com.example.lsc_app` and the **actual installed/release signing certificate SHA-256 fingerprint**. Do not substitute a guessed or temporary CI debug signer. Retain website fallback and verify the link association on a real phone. Custom-host association is not claimed.

### Push and upload progress

No Firebase setup exists in this project, and none was introduced. Push still requires approved FCM/server configuration and verified destination handling. HTML upload network percentages and server success cannot be reliably inferred from file selection or document loading; only actual attachment checking and native download/save operations have native status feedback.

### Signing and publication

This task produces a **local debug APK**, not a production release. Source is published only to the approved `ui-fix` branch; exact hosted-run outcomes and artifact identities are recorded in the external delivery evidence, not assumed by this document. It uses the existing local debug key. Its certificate can differ from a previously supplied hosted debug APK or the user's release build. Updating an installed package requires that package's original signing key. Do not uninstall or clear data to work around a mismatch. No release key/password was read or copied.

The separately diagnosed external-browser missing-session-cookie failure is not asserted fixed by these UI changes.
